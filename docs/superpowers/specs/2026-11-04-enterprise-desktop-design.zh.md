# 企业桌面客户端设计

[English](2026-11-04-enterprise-desktop-design.md) | 中文

## 摘要

桌面客户端提供企业工作台，同时把 Agent 执行、本地工具、终端、文件处理和浏览器渲染从服务器迁移到用户电脑。企业服务继续作为身份、团队成员、权限、共享资源、模型访问、计费、审计和客户端策略的权威来源。这是云端控制面加桌面执行面，不是企业控制台的本地副本。

## 目标意图

桌面客户端用于降低每个团队在服务器上保持一套 Harness 运行时所产生的内存、进程和 Chromium 成本。用户仍须使用同一企业账号登录、处在同一团队边界内，并使用与 Web 工作台相同的共享文件、知识、技能、模型目录和 Token 额度。

## 目标

- 使用现有企业邮箱和密码账号体系登录。
- 在用户电脑上运行 Harness Host、Agent 会话、终端、本地工具、文件处理和浏览器。
- 在云端保留团队文件、知识、技能、权限、插件策略、模型选择、额度与审计，团队资源只在任务请求时读取。
- 让每个模型请求经过企业模型网关，从而完成用量计量，并避免渠道密钥进入客户端。
- 允许团队成员查看同一 Session，同时只有其所有者保留写入权限。
- 保留现有 Web 工作台，作为无法安装桌面应用时免安装入口。

## 非目标

- 离线工作或重连后的冲突合并。
- 本地运行企业控制台或企业 SQLite 目录。
- 为桌面用户启动服务端租户容器。
- 首个版本提供多团队成员关系或团队切换。
- 在线支付服务或远程执行集群。

## 约束

- 客户端登录、团队资源、模型请求、额度刷新和客户端策略都需要网络连接。
- 团队文件、知识和技能不在用户电脑上持久缓存；任务只能把它们临时放入私有目录，并在任务结束时删除。
- 首个版本只要求现有企业账号和密码登录方式。
- 现有企业模型为每个用户分配一个团队，桌面配置遵循该规则。
- Session 日志由企业服务保存；Session 所有者是唯一写入者，团队成员只读订阅。
- 首个支持的桌面平台为 Windows x64；Windows 版本验收后再支持 macOS。
- 服务部署继续能够提供当前 Web 工作台和远程 Chromium 浏览器。

## 架构

### 云端控制面

现有企业控制台继续保存用户、团队、角色、套餐、订单、用量、审计、模型渠道、运行时策略和权威团队资源目录。它新增桌面引导、按需资源读取、模型网关接口和 Session 同步服务。同步服务保存追加式 Session 日志、写入租约和面向团队成员的只读实时流。对于已登录的桌面会话，控制面不再启动租户容器。

### 桌面执行面

Electron 负责企业登录、安全令牌存储、云端请求、本地 DSH Host 生命周期、更新和原生能力。一个本地 Host 插件把 Harness 连接到云端引导、模型网关、按需资源读取、Session 同步、插件策略、额度提示和企业账号菜单。Agent 轮次和任务工作区文件在已登录用户的操作系统账号下本地执行。

### Web 回退

当前 Web 路径继续可用。浏览器用户仍启动团队租户，并使用服务端 Chromium 远程浏览器。两个客户端共享企业身份、团队资源接口、Session 同步、模型目录、额度和审计记录，差别只在执行位置。

## 登录与会话

桌面欢迎流程增加企业模式，用它替代模型 API Key 引导。Electron 主进程在隔离的网络会话中执行登录请求，把长期凭据保存在操作系统凭据库，只把短期企业访问令牌和云端基础地址交给本地 Host。访问令牌快速过期，刷新凭据绑定设备，退出登录只撤销该设备。

登录并解析团队后启动本地 Host。Electron 主进程通过本机回环控制通道刷新过期访问令牌，因此渲染进程和第三方插件永远接触不到刷新凭据。退出登录会停止 Host、清除内存令牌，并删除每个任务范围的团队资源目录。禁用账号或移除团队权限在下次授权或刷新检查时生效。

## 模型网关

控制面新增一个需要鉴权、按所选企业模型和渠道路由的透传模型网关。桌面请求携带企业访问令牌、团队、用户、所选模型和客户端生成的请求标识。引导结果告诉 Host 适用的供应商协议、路由、模型 ID、上下文窗口和能力，因此网关保留现有 Chat Completions、Responses 或其他渠道协议，而不是压平模型行为。网关在访问上游供应商前检查团队状态、套餐额度、模型访问和渠道状态。

网关转发流式与非流式响应、工具调用、推理字段、图片、取消操作和供应商错误。它根据供应商最终用量在服务端记录输入与输出 Token，并按请求标识对重试去重。额度在请求开始时按团队硬限制；已经开始流式传输的请求不会被中断，余额耗尽后的下一次请求按失败关闭。网关永不返回渠道 API 密钥或上游凭据。

## 共享资源

云端始终是团队文件、知识和技能的唯一权威来源。桌面引导返回团队资源目录、版本，以及通过已鉴权企业接口请求资源内容的能力。客户端不下载完整目录，也不保留可复用本地缓存。

任务需要团队文件、技能、技能参考或知识文章时，Host 才请求该条目，并把它放入只有所有者可访问的私有任务目录。任务规划期间可以获取知识摘要，完整文章正文和较大文件只在被选中时获取。生成的 `team-knowledge` 技能作为只读资源按需获取。

桌面端的团队资源为只读。编辑继续通过企业控制台或其他获授权的管理界面完成。任务物化的资源会在完成、取消、退出登录、Host 重启或有界超时后删除。获取失败会让请求它的操作失败，而不是回退到过期的本地内容。

## 会话与工作区

企业服务是每个 Session 日志的持久所有者。所有者的桌面 Host 执行轮次、写入本地追加式日志，并在 Session 超过配置的未确认事件上限前，把每个已确认批次同步到云端。检查点、任务工作区文件、终端进程和本地工具输出保留在所有者电脑上，除非某个工具显式把它们写入 Session 事件。Session 不共享任意本地工作区文件。

客户端为企业服务器和用户使用独立的本地配置，因此切换账号或服务器不会复用其他身份的 Session 存储。配置同时记录企业服务当前分配的单一团队。在新设备上，所有者下载完整 Session 日志并取得写入租约后才能继续。

## 共享会话

每个 Session 记录团队、所有者、可见性、格式版本和当前写入租约。只有所有者可以追加事件。桌面端在开始轮次前取得可续期租约；租约丢失会在下一次模型或工具调用前停止当前轮次。同一用户的另一台设备可以在租约被占用时读取，并在前一租约过期后接管。

团队成员通过只读 Session 接口打开共享 Session。他们获得完整可回放日志和进行中轮次的实时事件流。客户端渲染相同的转录和工具卡片，但禁用消息输入、排队、审批和写入操作。读取 Session 永远不会取得写入租约。需要继续工作的团队成员会新建 Session，而不是向共享 Session 追加。

共享 Session 对所属团队的每名有效成员可见。Session 日志保留在企业服务中，直到所有者或获授权的管理员将其删除；首个版本不自动过期。只读查看者会把仅存在于本地的产物视为不可用，除非所有者已通过企业资源或附件路径上传该产物。

## 浏览器

桌面端继续为侧边栏浏览器使用现有 Electron 浏览器 guest。它不得把企业远程浏览器接口注入本地工作台，因为由客户端完成浏览器渲染才能移除服务端 Chromium 成本。Web 用户继续使用远程 Chromium 路径。两条路径都保留当前地址校验和会话隔离。

## 插件策略

桌面 Host 只加载内置插件和云端策略返回的企业批准包。管理员继续控制内置插件与企业包；成员不能添加绕过策略的本地插件。企业服务签名批准清单，桌面构建固定服务公钥，密钥轮换需要签名的应用更新。客户端校验清单签名，并拒绝身份、版本、平台或内容哈希与批准记录不一致的包。

## 安全与隐私

客户端把刷新凭据保存在 Windows 凭据管理器或 DPAPI 中，并使其远离渲染进程、URL、日志和插件环境。物化的团队资源只存在于只有所有者可访问的任务目录中，并会自动删除。服务端会重新授权每个引导、资源和模型请求；本地策略是附加检查，不是权威来源。

企业插件和本地工具只能通过 Host 的正常工具权限访问本地文件。云端策略可以限制插件允许列表、工作区范围、审批模式和网络出口；策略缺失或无效时按失败关闭。退出登录以及切换账号或服务器会删除每个任务范围的资源目录，并在云端确认同步后删除本地 Session 副本。服务端审计记录桌面登录、引导、模型用量、资源读取、Session 访问和插件策略变化，但不记录提示词、终端输出或文件内容。企业模式关闭消费者分析，并把崩溃报告提示改为企业支持策略。

## 失败行为

- 云端不可用会阻止新的登录、引导、模型调用和共享资源写入；客户端保留本地状态可见，但拒绝新工作。
- 访问令牌过期会暂停模型和资源请求，直到 Electron 主进程完成刷新；会话被撤销会拆卸 Host 并返回企业登录。
- 资源获取失败会让请求它的工具或技能失败，而不是用过期或不完整内容继续运行。
- Session 同步失败会在超过未确认事件上限前暂停新的模型和工具工作；所有者保留可见的本地转录并重试，不创建分叉的云端历史。
- 模型网关拒绝会保留本地 Session，并显示类型化的额度、权限或渠道错误，不做无限重试。
- Host 崩溃会重启本地运行时，但不重放有副作用的工具调用；用户回到最后一个持久 Session 检查点。

## 分发与更新

现有已签名的 Windows 打包与自动更新通道继续作为分发机制。企业模式作为独立品牌的 Windows 应用和独立更新通道分发。企业构建固定云端基础地址、更新通道和最低支持版本；成员不能把应用改指向其他服务器。云端策略可以要求更新后再引导，但桌面更新永远不会替换企业数据或凭据。TLS 检查代理和企业自定义证书机构不在首个版本范围内。

## 分阶段交付

第一个里程碑交付企业登录、本地 Host 启动、令牌刷新、仅所有者可写的 Session 同步和带额度控制的模型路由。第二个里程碑交付只读共享 Session、按需资源读取与任务清理、企业账号界面、浏览器验收和插件策略。第三个里程碑强化失败恢复、临时资源清理、Windows 签名和 Windows 验收。整个过程保持 Web 租户和远程浏览器可用。企业管理员在系统浏览器打开云端控制台；桌面应用不内嵌管理控制台。

## 验收标准

- 企业成员使用邮箱和密码登录，在没有服务端租户容器的情况下进入本地托管工作台。
- 每个模型请求都经过企业网关、消耗团队额度、进入用量和审计，并在额度耗尽时按失败关闭。
- 团队文件、知识和技能只为请求中的任务获取，任务结束后消失，并且不会跨团队或跨账号串联。
- 团队成员打开同一 Session，能够看到所有者的实时和已完成转录，但不能追加、审批或控制工具。
- 桌面浏览器通过本地 Electron guest 渲染，而 Web 用户仍获得服务端 Chromium 浏览器。
- 退出登录会停止本地 Host、删除任务范围的团队资源，并在渲染进程和插件环境中留下不可复用的刷新凭据。
- 网络中断会用可操作状态阻止新的引导、资源写入和模型调用，而不是静默回退到直连供应商。
