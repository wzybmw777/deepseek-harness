## 2026-11-08 补充确认：单一工作台与项目目录

- 套餐、团队积分和智能体市场在当前工作台内使用，普通操作无需另开页面。
- 点击套餐／积分展示简要进度、可用与预留积分；管理员需要查看明细时，再主动进入网页管理详情。

- 新建项目的目录选择调整为织流自己的简洁样式，保留现有组件、交互顺滑程度与工作区管理逻辑。
- **网页目前仅作预览调试**，选择项目时浏览当前团队在服务器上的沙箱目录，可进入子目录、返回上层、新建文件夹并确认使用。

- 既有套餐进度与新增智能体积分钱包目前分别统计，前台明确区分，后续全量积分计费仍需继续接入。

## 1. 我理解的产品形态

**织流是一款同时支持个人与团队的 AI 助手：首批主打短视频创作，围绕爆款文案复刻、爆款短视频复刻提供专项智能体；用户输入需求、提供材料、结合知识库完成任务，通过分层套餐与积分解锁使用能力。**

用户首先接触到一个易用的默认助手。对于有明确用途的专项能力，可以从简洁的智能体入口了解、试用和解锁。模型、执行模式、插件及工具如何配合，尽量由产品在后台处理。

短视频复刻的目标交付物明确为视频成片。当前可先用一个搭载 PPT Master 技能、交付演示文稿的智能体作为市场和成果交付的验证样例，再继续扩充智能体类型；市场结构应支持持续扩展。

整体仍然沿用现在的聊天工作区。当前这一轮的设计重点是精简可见内容、调整品牌样式，而不是重新搭建一套操作结构。

用户对现有 UI 的补充是本次视觉设计的主要依据：**“这个肯定要保留，就是稍微变化下样式，但是我也喜欢这种简洁风格。”**

因此，前面讨论过的独立任务首页、全面调整导航等方案，本轮仅作为参考，不作为默认实施范围。

## 4. 设计原则

1. **默认就能开始。** 用户输入需求或上传材料后，即可进入任务，技术配置放在后台处理。
2. **熟悉且轻巧。** 复用当前工作区和交互，只增加任务确实需要的界面内容，保持简洁和连续的操作体验。
3. **付费价值看得懂。** 用户能了解某项付费能力适合什么任务、需要什么材料、会交付什么，以及如何计费。

## 5. UI 如何变化

### 5.1 整体视觉方向

建议延续克制的现代极简风格：清晰的文字层级、适度留白、细边界、少量强调色和短促自然的动效。

第一轮通过下列位置形成品牌差异：

- **品牌区**：织流名称、Logo、欢迎语及页面标题。
- **主题色**：选择一个品牌强调色，用于主按钮、选中状态和少量重点反馈；具体色值待看方案后确定。
- **侧边栏**：精简入口，统一图标、选中背景和间距，保留现有折叠与切换手感。
- **输入框**：整理底部按钮，调整边框、圆角和留白，让主要操作更清楚。
- **空白首页**：提供简短引导和少量任务示例，避免堆叠功能介绍与推荐卡片。
- **智能体入口**：沿用当前组件语言，清楚呈现用途、使用状态和解锁信息。

聊天内容仍应占据主要视觉空间。会员和推广信息保持克制，尽量在用户主动查看权益或使用相关能力时出现。

### 5.2 建议的入口组织

这是基于现有布局的精简建议，最终以界面稿为准：

| 位置 | 建议呈现 | 说明 |
| --- | --- | --- |
| 左侧栏 | 新对话、历史记录、知识库、智能体入口 | 继续沿用当前聊天工作区的使用习惯；具体分组与排列待界面稿确认。 |
| 主区域 | 对话、当前任务状态、成果入口 | 默认助手作为主要使用路径。 |
| 输入区域 | 输入、上传、发送／停止 | 其他操作按需放入更多菜单；具体按钮逐项盘点。 |
| 文件／预览区域 | 任务材料、生成文件、预览和下载 | 复用现有能力，按需打开。 |
| 头像菜单 | 账户、会员／用量、少量偏好设置 | 将低频功能集中起来，维持首页简洁。 |

“我的成果”是否需要独立入口，先评估现有历史记录与文件面板是否足够。第一版优先利用现有界面承接。

### 5.3 功能可见性建议

| 层级 | 内容举例 | 建议呈现方式 |
| --- | --- | --- |
| 常用 | 输入、上传、发送、停止、历史记录、查看成果 | 默认可见。 |
| 知识管理 | 查看与维护知识、供助手参考 | 保留明确入口；按现有读写权限展示操作。 |
| 专项与付费 | 选择智能体、查看权益、余额／额度 | 保留清晰入口，在相关场景展开。 |

任务失败原因、需要用户确认的操作和额度变化，应给出清楚反馈，保证界面精简的同时，用户仍能掌握任务状态。

## 6. 模式、专家与智能体的产品关系

### 6.1 一个默认执行入口

建议普通用户直接使用默认助手，前台隐藏标准模式以外的技术模式选择。标准模式目前已经覆盖文件、数据、脚本及常见任务处理，但首发任务仍需要逐项验证效果。

用户已添加的限制继续在服务端执行。前台隐藏模式属于体验调整；实际工具权限、额度、目录范围、时长和并发需要由后台规则落实。

### 6.2 对“专家”的准确理解

| 概念 | 作用 |
| --- | --- |
| 角色／系统提示词 | 规定职责、处理要求、回答和交付标准。 |
| Skill | 提供完成某类任务的方法、流程与配套资源。 |
| 工具与知识库 | 提供实际操作能力和参考资料。 |
| 智能体 | 根据目标组织和调用可用能力，持续完成任务。 |
| 专家团 | 多个角色分工协作，再汇总形成交付物。 |

已安装的专家插件提供专家及专家团能力。根据插件说明，专家继承当前会话模型；每个专家是否配有独立 Skill 或知识库，需要分别核对。

建议产品前台统一使用“智能体”这一称呼，卡片名称突出用途。首批以“爆款文案复刻”“爆款短视频复刻”为主，展示各自需要的材料及交付示例。

专家团可以作为部分专项服务背后的执行方式。用户主要选择要完成的任务，系统再决定如何组织协作；涉及额外收费时，启动前明确告知。

### 6.3 知识库：明确保留的核心能力

用户已明确要求保留知识库。以下为 2026-11-06 对当前分支源码和租户配置的核查结果：

- **前台插件**：`@deepseek-ai/dsh-client-ui-enterprise-resources`，同一插件提供文件、知识库与技能面板。
- **后台存储**：企业控制台处理知识条目的列表、新建、编辑和删除。各团队的条目保存在服务端自身目录内的 `resources/knowledge/articles.json`。这里的文件位于运行服务的服务器磁盘，并非用户浏览器或个人电脑。
- **内容结构**：标题、摘要、正文、标签及时间信息。当前是条目编辑式的轻量知识库。
- **供 Agent 使用**：知识变化后自动生成 `skills/team-knowledge/SKILL.md` 及条目 Markdown 参考文件，由现有技能发现机制和 Agent 按需加载。
- **现有权限**：团队成员共享同一团队知识；写操作要求资源写权限。当前这一套属于团队知识库，独立的个人私有知识空间需要另行设计。
- **现有限制**：每团队最多 500 条，知识条目 JSON 总大小上限 4 MiB，单条正文上限 128 KiB。这是当前实现上限，后续套餐设计另行确定。
- **另一条接入**：租户配置还包含飞链知识库的 MCP 连接，使用 Streamable HTTP。用户已确认飞链在同一服务器上独立维护。此次确认了接入配置的存在，尚未验证其当前检索可用性；已核对的侧栏面板和条目读写、生成技能链路没有连接飞链，两个入口不应视为同一数据源或自动同步。

侧栏条目库这条实现通过生成技能和参考文件提供知识，尚未在这条链路中发现文档自动切块、向量索引及语义召回处理。后续设计需要分别评估轻量条目库与外接检索服务，避免把两者默认视为同一套数据。

产品建议：保留简单的知识库入口，让用户管理材料，并让默认助手和专项智能体在权限范围内使用。文件上传后是否自动解析入库、支持哪些格式、如何显示引用、如何选择本次使用的知识库，均属于待确认的后续设计，当前尚未承诺已经具备。

用户已确认后续采用服务端／飞链统一管理知识的方向，织流提供简洁的界面和权限范围内的调用。内置条目库如何整合、是否保留为简短团队说明，需要在完成数据盘点后确定；现有数据的停用、删除和迁移方案尚未确定。

### 6.4 已确认：知识由服务端统一管理，支持跨设备使用

**产品要求：客户端负责界面，知识统一由服务端／飞链管理，网页端和客户端访问同一份权威知识数据，按账户与团队权限使用。**

| 层级 | 职责 |
| --- | --- |
| 网页端／客户端 | 提供知识入口、展示、操作与调用反馈，连接统一服务端。 |
| 织流服务端 | 识别登录账户和团队，执行访问权限校验，承接知识访问与智能体调用。 |
| 飞链知识库 | 作为独立维护的知识系统，承担正式知识内容的管理与检索；具体接口和接入范围在实施前核实。 |
| 设备本地缓存 | 如有需要可用于改善体验；设备缓存不作为知识的唯一保存位置。 |

预期行为：

- 用户在另一台设备登录同一账户、进入同一团队后，可以访问同一批有权限的知识，无需手动复制设备上的知识文件。
- 默认助手和专项智能体在用户权限范围内使用统一知识，服务端校验实际知识调用，前台显示范围与调用范围一致。
- 知识内容更新后，各端重新读取时能获得服务端最新内容；缓存失效与刷新方式在实现时确定。
- 初始部署复用当前服务器上独立维护的飞链。统一的是数据来源与访问权限，后续服务部署位置可按需要调整。

这一要求针对知识库。对话、生成文件和其他设备设置是否跨端同步，以及离线使用、缓存加密、冲突处理等细节，分别另行定义。

当前已经核实浏览器知识面板将条目保存到服务器；飞链接入、跨端统一入口与权限映射仍需实施和验收，本文将目标行为与现状分开记录。

### 6.5 已确认：独立账户绑定与企业自助开通

**当前路线：两个项目各自运行，通过绑定使用飞链知识库。织流企业版可提供飞链自助开通入口，账号密码允许设置相同；飞链套餐与织流套餐分别管理。**

| 用户状态 | 产品行为 |
| --- | --- |
| 已绑定且授权有效 | 登录织流后，通过有效授权加载可访问知识库，正常使用无需反复输入飞链密码。 |
| 已有飞链账户但未绑定 | 引导验证飞链账户并授权绑定，复用原有知识库和飞链权益。 |
| 尚未开通飞链 | 默认保留入口，提供注册／开通引导。 |
| 织流企业版用户需要飞链 | 提供飞链企业版自助开通入口，按飞链规则创建或关联账户及企业空间，随后完成绑定。 |
| 已开通但暂无知识内容 | 展示空知识库与添加资料引导。 |
| 授权失效或被撤销 | 提示重新授权，按飞链当前权限与套餐状态访问。 |

边界与实施要求：

- **账户独立**：两侧各自管理账户，可设置相同账号密码；相同密码属于用户可选择的设置，不代表已经统一身份。改密与重置按各自账户体系处理，密码同步暂缓。
- **套餐独立**：织流企业用户自助开通获得飞链企业版，但两侧套餐定义各自管理。具体飞链企业档位、额度、是否赠送、费用及有效期另行确定。
- **数据独立**：知识由飞链维护，织流通过受支持接口读取或检索；两侧账户库与业务数据库保持独立。
- **绑定持久化**：服务端保存织流账户／团队与飞链账户／租户的映射及适当授权，供网页端与客户端复用；解绑只解除访问关联。
- **按授权使用**：绑定不扩大知识权限，调用继续遵循飞链的成员、知识库和套餐限制。
- **自助开通可恢复**：优先使用既有开通流程或受支持接口，处理重复提交与部分失败，避免重复创建账户。需要改动飞链时，先给出具体改动范围供审阅。
- **故障影响收敛**：飞链连接失败时，知识库入口展示状态，织流的基础助手与独立账户服务继续可用。

待确定：飞链企业版具体档位和开通费用／赠送有效期、普通注册是否沿用邀请码、绑定归个人还是团队、成员如何获得授权、解绑／换绑规则及权限刷新方式。

### 7.3 已确认：积分计费与管理员定价

- 使用积分承接运行消耗和智能体解锁，用户使用已有余额消费，余额不足时再进入充值或升级流程。
- 智能体解锁费购买相应期限的使用资格；解锁后的每次运行继续按正常规则累计实际用量并扣积分，消耗随使用增加。
- 管理员可配置每 1M Token 扣多少积分，其中 1M 为 1,000,000 Token；具体积分数值待成本核算后配置。
- 建议支持按模型、渠道及输入／输出／缓存等计价类别配置，具体计价维度在后台设计时确定。不同类别按实际用量分别换算积分后汇总。
- Token 明细保留在服务端计量和管理端；用户侧展示积分余额、消费记录、剩余用量及费用规则。
- 费率应有生效时间与版本，流水保存所用费率和用量，保证价格变化后历史消费仍可核对。
- 小额消耗的精度、累计和舍入规则需统一，避免逐片段舍入造成额外扣费。
- 团队积分、成员额度、消费权限及智能体授权范围仅由管理员配置，服务端执行对应规则；成员按已分配权益使用。具体消费是否需要逐次审批仍待确定。
- 视频生成、配音、素材等存在非 Token 计量成本时，应在接入相应服务前定义管理员可配的积分换算规则；具体维度及价格待核算。

织流内部运行消耗与智能体解锁使用统一织流钱包和流水，飞链继续按自己的套餐与账本运行。绑定本身不合并两边余额或套餐；需要明确飞链服务可能发生的费用，以及织流对知识检索是否另计积分的规则，供用户在使用前了解。跨项目钱包合并暂缓。

### 7.4 已确认：当前 30 天授权，预留可配时长与永久授权

用户查看智能体用途、成果示例、解锁积分价格和有效期 → 确认使用积分 → 服务端扣除余额并授予使用权 → 从购买成功时起连续使用 30 天 → 到期后可再次使用积分解锁。

- 解锁使用已有积分余额，日常购买无需每次重新充值。
- 当前期限明确为购买成功后的 30 天，到期时间按购买成功时刻加 30×24 小时计算，由服务端统一校验并在前台显示。
- 授权结构区分“固定期限”和“永久”；固定期限支持配置时长，当前市场商品默认 30 天。永久授权未来可以启用，不使用极远到期日期模拟永久。
- 商品配置建议分别保存授权类型、时长、积分价格和生效版本；购买记录保留当次配置快照、开始时间和到期时间。永久授权使用明确类型表达，无到期时刻。
- 后续从 30 天改为其他时长或永久时，建议默认影响新购买；是否追溯调整既有权益另行定义。
- 到期后可再次解锁；自动续费、提前续期与剩余时长叠加规则尚未确定。
- 解锁费对应使用资格，运行另按正常积分规则计费。商品详情和购买确认处需同时说明使用期限、解锁积分及运行仍会产生积分消耗，避免产生不限量使用的预期。
- 扣积分与授权应作为同一次购买处理；重试和重复点击复用同一订单，失败后可恢复，避免重复扣费或扣费后无权益。
- 团队购买后的使用人、席位与共享范围由管理员配置；成员按分配结果使用，权益设置仅限管理员操作。

付费价值由任务流程、成果质量、专用资料和工具能力支撑，具体商品仍需验证效果和成本。

## 8. 关键用户流程

### A. 使用默认助手

打开织流 → 输入需求／上传材料 → 直接发送 → 查看简短进度 → 获取回答或成果 → 继续修改／下载。

首次使用尽量减少配置。对生成文件的任务，完成后提供明确的预览和下载入口。

### B. 使用专项智能体

打开智能体入口 → 查看用途和成果示例 → 试用或查看费用 → 解锁／确认使用 → 提供材料 → 开始任务 → 获取成果。

建议继续复用当前聊天界面，在对话中清楚标识正在使用哪个智能体。切换智能体是否新建对话，以及历史上下文如何处理，待交互设计阶段明确。

### C. 查看与继续历史任务

打开历史记录 → 查看原对话及关联文件 → 补充要求 → 继续处理。

这一流程先复用现有历史与文件能力，后续根据实际使用反馈决定是否需要独立成果库。

### D. 换设备使用知识库

在新设备打开网页或客户端 → 登录同一账户 → 进入同一团队 → 从统一服务端加载有权限的知识 → 继续向助手提问或使用智能体。

验收时应确认知识来自同一数据源，并确认其他账户或团队的私有知识保持隔离。

### E. 首次绑定飞链与后续使用

普通用户首次未开通：登录织流 → 打开默认提供的知识库入口 → 注册开通或绑定已有飞链账户 → 完成验证／授权 → 服务端保存关联 → 加载知识库或展示添加资料引导。

后续已绑定：登录织流 → 自动识别账户关联 → 加载知识库 → 直接使用。更换设备后仍复用服务端关联状态；授权失效时再提示重新授权。

企业版用户：登录织流 → 选择“开通飞链知识库” → 按飞链规则自助开通企业版或选择已有账户 → 完成绑定 → 使用有权限的知识库。两侧账号密码可设置相同，套餐分别生效。

### F. 积分解锁智能体

查看智能体 → 查看当前商品的积分价格与 30 天有效期 → 确认兑换 → 扣积分并授予权益 → 从购买成功时刻起使用 30 天 → 到期后再次兑换。余额不足时再提示充值；是否自动续期另行确定。

有效期内每次执行仍按实际用量扣正常积分，扣费规则与使用权分别校验和记录。

未来商品可展示管理员配置的其他期限或“永久使用”，同一授权流程按商品类型执行。

### G. 管理员配置智能体与团队权益

配置智能体系统提示词与 Skill → 设置市场商品价格与授权期限 → 试运行并发布 → 用户在前台使用。

团队管理员在授权范围内配置团队积分、成员消费权限和智能体使用权益；普通成员查看并使用已分配能力。平台商品运营与团队配置的具体管理员角色划分待实施设计。

| 文件与预览面板 | 保留，优化成果入口的可发现性。 |
| 知识库面板与知识使用链路 | 明确保留；接入统一服务端／飞链，落实跨设备访问与权限校验，再细化导入、检索和引用体验。 |
| 专家选择入口 | 评估改造成面向普通用户的智能体入口。 |
| 智能体介绍、试用与解锁界面 | 根据现有组件能力改造或补充。 |
| 智能体与市场管理后台 | 支持管理员配置 Skill、系统提示词、商品价格、授权类型／时长和上下架。 |
| 团队积分与权益后台 | 由管理员配置成员额度、消费权限及智能体授权范围。 |
| 会员、权益与额度展示 | 复核现有实现后接入。 |

任何涉及容器尺寸、消息高度或滚动区域的变化，都需要回归验证，以实际操作确认流畅感得到保留。

## 10. 响应式与基本可用性

以下是设计建议，设备优先级尚待确认：

- 桌面端保持现有聊天工作区和按需打开的文件／预览区域。
- 窄屏下侧边栏与预览面板按需展开，优先保证输入和阅读空间。
- 长文本、代码块、文件名与表格避免撑坏页面布局。
- 保持键盘操作、可见焦点、图标按钮名称和清晰的状态反馈。
- 正文对比度建议至少达到 4.5:1，重要触控目标建议达到 44×44 CSS 像素。
- 沿用并验证减少动态效果偏好的处理，动效保持轻量。

## 11. 建议的实施顺序

1. **确认本需求文档**：确定用户场景、首发范围和需要隐藏的入口。
2. **做一版小幅 UI 样式预览**：先验证品牌色、侧边栏、输入框和空白首页，检查是否保留现有手感。
3. **收敛前台功能**：落实默认执行方式、简化设置与任务过程展示。
4. **知识库绑定与自助开通**：盘点内置知识数据，复用飞链授权接口，明确个人／团队绑定范围，提供企业自助开通入口及跨设备复用；保持两个项目的账户、数据库和套餐独立。
5. **打磨智能体与可扩展市场后台**：可先接入 PPT Master 技能，用 PPT 智能体验证市场、解锁、运行计费及成果交付；继续完善文案复刻和视频成片交付链路，实现 Skill、系统提示词及市场商品的后台管理。
6. **补齐付费闭环**：落实织流个人／团队套餐、管理员可配积分费率、团队权益配置、织流内部钱包、30 天授权及后续时长／永久扩展。

当前开发与验收继续使用已确定的预览入口：<https://dev.echoai.best/yituobo/>。

## 12. 建议的验收标准

- [ ] 新用户进入主界面后，可以直接找到输入、上传和发送操作。
- [ ] 完成基础任务时，无需理解执行模式、插件或模型渠道配置。
- [ ] 首屏入口比当前更少，常用操作仍容易找到。
- [ ] 整体仍保留当前简洁风格，品牌与关键控件有织流自己的辨识度。
- [ ] 输入、消息更新、滚动、切换、面板展开收起保持流畅，无明显新增跳动或卡顿。
- [ ] 用户可以查看任务进度、停止任务，并在失败时获得下一步提示。
- [ ] 生成的成果能清楚地预览、下载和继续修改。
- [ ] 知识库入口保留，现有知识的查看、维护与 Agent 按需使用经过验证，团队权限保持有效。
- [ ] 网页端与客户端连接同一知识服务；换设备登录同一账户、进入同一团队后，可访问同一份有权限的知识。
- [ ] 知识更新后，各端重新读取能获得一致的最新内容；设备本地缓存不作为唯一知识副本。
- [ ] 知识访问与智能体检索均通过服务端权限校验，其他账户或团队的私有知识保持隔离。
- [ ] 已关联且授权有效的用户登录织流后可直接使用相应飞链知识库，日常操作无需再次登录飞链。
- [ ] 未关联用户可通过清楚的一次绑定流程接入；关联状态保存在服务端，换设备后无需重新绑定。
- [ ] 登录后默认提供飞链入口，普通未开通用户可获得注册／绑定引导，已开通用户可直接访问。
- [ ] 织流企业版提供飞链企业版自助开通入口，开通后可完成绑定，重复提交得到正确处理；两侧套餐各自生效。
- [ ] 两侧账户可设置相同账号密码，并继续由各自体系管理；两个产品的套餐、权益、数据库和余额保持独立。
- [ ] 飞链暂时连接失败或解除绑定时，织流基础助手与账户服务仍可使用；解绑保留原有知识内容和账户。
- [ ] 首次关联验证目标账户身份；授权撤销或失效后，停止沿用过期权限并展示重新授权入口。
- [ ] “未绑定”“已绑定但暂无知识库”和“需要重新授权”分别给出准确反馈。
- [ ] 用户在使用付费能力前能理解用途、权益和费用规则。
- [ ] 已购买权益与服务端实际调用限制一致。
- [ ] 个人版与团队版均有分层套餐展示，说明能力与相对用量，套餐页不展示具体 Token 配额。
- [ ] 管理员可配置按每 1M Token 换算积分的规则，服务端按实际用量计费，消费流水可追溯。
- [ ] 用户可用积分兑换智能体购买成功后连续 30 天的使用权，前台显示准确到期时间，服务端校验生效与到期。
- [ ] 授权类型与时长可配置并预留永久授权，历史购买保留当时的规则，配置变更不意外重写既有权益。
- [ ] 团队积分与智能体权益仅允许管理员设置，成员只在分配范围内使用。
- [ ] 短视频爆款复刻完成视频成片生成、预览和下载，具体规格按实施前确认的要求验收。
- [ ] PPT 智能体调用经验证的 PPT Master 技能并交付演示文稿；按选定上线顺序验证市场闭环。
- [ ] 管理员可继续添加智能体配置；不同技能和成果类型复用市场与购买流程，新执行能力按需接入验证。
- [ ] 已解锁用户运行智能体仍按实际用量扣正常积分，解锁购买与运行消费分别记录且规则清楚。
- [ ] 管理员可在后台管理智能体 Skill、系统提示词及市场商品；普通用户没有配置与发布权限。
- [ ] 织流积分扣费与权益发放一致，流水可核对；飞链独立费用与织流费用的规则展示清楚。
- [ ] 现有账户、会话、历史与文件访问经过回归验证。

## 15. 交互补充：对话作为统一使用入口

- 智能体沿用专家团的 @ 选择方式，市场只承担发现、分类、解锁和权益展示。无需到市场里的独立任务表单提交材料。
- 飞链知识库默认在织流工作台内打开，直接展示绑定状态和可访问知识库；使用知识库也进入 @ 对话。保留织流原有知识库作为次级入口。
- 不设置“我的作品”入口。用户从原有历史记录找到智能体的输入、执行状态、回复与生成文件，在对应对话中下载。
- 付费解锁、有效期、运行权限和实际用量积分结算继续由服务端执行；提示词与 Skill 由管理员管理，普通用户只看用途和成果。
- 飞链与织流继续通过绑定关联，分别维护账号、套餐、数据库与计费。默认知识库面板不自动跳转管理网页。
